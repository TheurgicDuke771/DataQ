**Long lists can be paged by cursor.** `/runs`, `/pipeline_runs` and `/incidents` return an `X-Next-Cursor` header while there are more rows; send it back as `cursor` (instead of `offset`) for the next page. A page then costs about the same however deep it is, where a large `offset` costs in proportion to itself: 500,000 runs deep, 1.1 ms against 79 ms. Offset paging is unchanged. Incidents sort by when they last breached, so an incident that breaches again while you page can be missed; none is returned twice.
