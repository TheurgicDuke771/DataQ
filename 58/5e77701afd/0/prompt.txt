  ## What it does
  DQX checks get an optional `mode`: `snapshot` (the default, unchanged) or `stream`. Stream mode evaluates only the rows appended to the table since the check's last saved result. The design is written up as a short ADR 0036 amendment in the same PR.
  
  - **Evaluation:** it runs inside the existing one-serverless-job-per-run. The notebook reads the table with `readStream` and `trigger(availableNow=True)` into a `noop` sink. Failing rows per rule are summed from the stream's observed metrics, so no rows are ever collected and nothing is written.
  - **Resume point:** DataQ holds it, not a Spark checkpoint.
    - Each result records `observed_value.stream.next_version`, the Delta version the stream reached.
    - `run_service.latest_evaluated_observed` reads the latest evaluated (not skip or error) result per check and passes it to the batch hook as a new `previous` argument.
