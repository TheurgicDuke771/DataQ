## Problem statement / context
DataQ is a single-tenant data-quality platform (FastAPI + Celery + GX + React; repo
`TheurgicDuke771/DataQ`, local checkout `~/Coding/Python/DataQ`, conda env `dataq`,
shell is fish/zsh via the Bash tool). It stays a **cloud-hosted product** (Azure/AWS
reference deployments remain the preferred production path). We are retiring only
**our own paid dev/test cloud estate** (AWS, Azure, Snowflake, Databricks) for cost.
After that, development and testing run on the local stack; anything cloud-specific
that can't be run live gets the `needs-cloud-verification` label and is tracked in
**#2224**. **The clouds still exist right now**, so use them while they do: deploy,
live-verify, then plan and execute the teardown (items 1–3 below).

Standing rules (from the user and CLAUDE.md, still in force):
- One functionality per commit. Tests for each change, and **prove a regression
  test fails without its fix**. Run `/code-review --comment low` on every PR (the
  review agent, never a self-review). Fix findings in the same PR, or file an issue.
  Squash-merge.
- **Migrations are additive and ship in their own PR, ahead of the code that uses
  them.** Test up and down locally on a populated scratch DB. For CHECK constraints,
  add them NOT VALID and VALIDATE in an autocommit block. Build indexes CONCURRENTLY.
  Make the migration safe to re-run.
- Never commit a credential. Read secrets inline only; never print them or write
  them to files. Never `cat`/parse `secrets.sh`; only `source` it inline. No
  `--no-verify`.
- **Confirm before any cloud or infra change.** Log every infra change in
  `docs/ops-log.md` with UTC timestamps; write "maintainer's IP", never the address.
  Never touch the harness ADF triggers (`tr_orders_landed`, `tr_customers_daily`,
  both `Stopped`).
- Run the **whole** frontend suite (`pnpm test:coverage`) and the whole backend
  suite (`pytest backend/tests`; no xdist, so no `-n`) before pushing. After any
  backgrounded `git push`, confirm it landed with `git ls-remote --heads origin
  <branch>` against `git rev-parse HEAD`.
- Published docs (`docs/site/`) may not cite ticket numbers; a pre-commit hook
  enforces this.
