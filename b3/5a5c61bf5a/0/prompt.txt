  ```tsx
  <Filter label="Actor user ID">
    <Input ... />
    {actorError && (
      <Typography.Text type="danger" style={{ fontSize: 12 }}>
        Not a valid ID — paste the UUID from the Members table, not an email.

  </Filter>
  ```
  
  `Filter`'s new implementation is:
  ```tsx
  const child = isValidElement(children) ? (children as ReactElement<{ id?: string }>) : null;
  const controlId = child?.props.id ?? generatedId;
  ...
  <label htmlFor={controlId}>...</label>
  {child ? cloneElement(child, { id: controlId }) : children}
  ```
  
  When a `Filter` call site has more than one JSX child (here: the `Input` plus the conditional `Typography.Text`), React always compiles this to an **array** of children — `[InputElement, (actorError && TextElement)]` — regardless of whether `actorError` is truthy or falsy at runtime (a falsy conditional still occupies a slot in the array, it doesn't vanish from the compiled arguments). `isValidElement(children)` therefore returns `false` unconditionally for this call site, `child` is always `null`, `controlId` falls back to the unused `generatedId`, and the raw `children` (the `Input` with no `id`) is rendered as-is.
