## Report

**Angle 1 — Altitude**

1. **`backend/app/datasources/sql.py:150-159` (`core_table`, lines ~226-231)** — The whole mechanism depends on two undocumented internal behaviors: `IdentifierPreparer.quote()` special-casing a `quoted_name(..., quote=False)` marker to skip its own reserved-word/quote-necessity logic, and `format_table()`'s `effective_schema = schema_for_object(table)` being falsy only because `schema=None` is passed. Neither is part of SQLAlchemy's documented composition contract for "pre-assemble a multi-part namespace." *Failure scenario:* a future SQLAlchemy point release that changes how `format_table` treats a table whose "name" already contains dots (e.g. adding its own dot-splitting for compatibility with 3-part BigQuery names) would silently re-break exactly the case this PR fixes, and nothing would catch it except the dialect-specific unit tests already in the repo — there's no invariant test asserting the underlying `quoted_name`/`schema=None` contract itself.

For a **foreign** (non-structlog) record it is the real tuple, as claimed.
