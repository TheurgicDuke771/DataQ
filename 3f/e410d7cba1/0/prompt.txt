### 1. `brace-expansion@5` override has no ceiling — the one override in the file that lacks one, and the commit message claims otherwise (confidence 88)

`/Users/arijit/Coding/Python/DataQ/frontend/package.json:68`

```json
"brace-expansion@1": "&gt;=1.1.18 &lt;2",
"brace-expansion@5": "&gt;=5.0.9",      ← no upper bound
"dompurify":         "&gt;=3.4.12 &lt;4",
"js-yaml":           "&gt;=4.3.0 &lt;5",
"undici":            "&gt;=7.29.0 &lt;8",
```

Four of the five overrides carry a ceiling; `brace-expansion@5` does not. This is exactly the #971 failure mode ("an open-ended `js-yaml: "&gt;=4.3.0"` let pnpm resolve onto the 5.x major"), and commit `23d35fc1` explicitly asserts the opposite:

&gt; Bumps the bounded overrides accordingly (**ceilings kept** — an open-ended range is what let js-yaml jump a major in #971).

The `@5` in the key is **not** the bound. It is a selector over the *declaring* dependency's range, not over the resolved output — which the adjacent line proves: if the key selector bounded resolution, the `&lt;2` in `"brace-expansion@1": "&gt;=1.1.18 &lt;2"` would be redundant. It isn't, and the author wrote it there but omitted the equivalent on the very next line.

Blast radius is concrete, not theoretical. `minimatch@10.2.5` declares `brace-expansion: ^5.0.5` (verified on the registry); the override rewrites that edge to `&gt;=5.0.9`. When `brace-expansion@6.0.0` publishes, pnpm resolves `minimatch@10` onto a major it never declared. brace-expansion ships majors at a real cadence (1→2→3→4→5 all live, per its registry doc), and its 5.0.0 major is precisely the one that dropped the default export and produced `TypeError: expand is not a function` in `minimatch@3` — the breakage #969 was created to record.

Git history confirms this is not new — `brace-expansion@5` has been unbounded since #971 (`0f1699e1`) — but per the project's "pre-existing is not a disposition" rule, and since this PR edits that exact line while re-asserting the ceiling claim, it should be closed here.

**Fix:** `"brace-expansion@5": "&gt;=5.0.9 &lt;6"`. Re-run `pnpm install --lockfile-only` and `node scripts/audit_bulk.cjs --audit-level=high` to confirm the lockfile is unchanged (it should be — 5.0.9 is current `latest`).
